**Context:** Review/ingestion of the `processa-deploy` skill documentation — covering SSL certificate management, nginx-proxy vhost setup, SSH inspection bootstrap, pre-deploy investigation checklist, and registry options for NIC projects on ia-web.

---

**Key Exchanges:**

- **SSL cert path mismatch**: `nginx-proxy` reads certs from `/projetos/proxy/nginx/certs/live/<domain>/`, not from `/etc/letsencrypt/` directly. Manual `cp -L` required after certbot issues cert. Certbot auto-renewal refreshes `/etc/letsencrypt/` but NOT the nginx-proxy path — needs re-copy every ~60 days or a deploy-hook in `/etc/letsencrypt/renewal-hooks/deploy/`.
- **`privkey.pem` → `private.key` rename**: certbot outputs `privkey.pem`; nginx-proxy expects `private.key` — the copy command must rename it.
- **SSH inspection bootstrap**: `bash <skill>/scripts/setup-local-ssh.sh` is idempotent; sets up `~/.ssh/` with host key, config block `Host iaweb`, and keypair. Key source priority: (1) GitLab group SSH_DEPLOY_KEY via GITLAB_ACCESS_TOKEN, (2) new keypair generated locally. After setup, all inspection is `ssh iaweb 'cmd'` — no ad-hoc credentials.
- **Pre-deploy investigation is mandatory** for pre-existing `/projetos/<app>/` directories — never `docker compose up -d` on unknown state.

---

**Lessons Learned:**

- Runtime container config (`docker exec … cat`) is the source of truth, not the repo. The Caddyfile in the running container may be ahead of the repo.
- Certbot renewal hook (`/etc/letsencrypt/renewal-hooks/deploy/`) is the correct long-term fix for the cert sync problem — avoids the ~60-day manual copy.
- `deploy-only` CI pattern (GitLab deploys image built externally) is dangerous if the external CI (e.g., GitHub Actions) is not triggered by commits on the actual source-of-truth. Observed failure: GHA built stale code from a GitHub mirror that was 18 days behind GitLab.
- When upstream is behind runtime: diagnose by comparing built HTML asset paths in the running container vs what the repo would generate. Restoring lost config is not scope creep — it's sync.
- `shared-net` / `web_network` cross-project networks must not be removed without inspecting membership first.
- `suporte` user may not be in the `docker` group by default on ia-web — `usermod -aG docker` needed in bootstrap.

### Session (22:00) - Authelia SSO integration + bootstrap mode fix

**Context:** Implementação da integração SSO com Authelia no hub (`agents.processa.info`), autenticação híbrida, criação automática de usuários SSO, bootstrap mode, melhorias na UI de gestão de usuários, deploy e validação em produção.

---

**Key Exchanges:**

- **Auth híbrida**: sob Authelia → `POST /auth/sso` lê headers `Remote-User/Email/Name`, emite JWT via cookie HttpOnly; sem Authelia → formulário de login manual. O hub tenta SSO no `beforeLoad` antes de redirecionar para `/login`.
- **`upsertSSOUser`**: cria `context/users/{slug}/USER.md` sem `credential.yml` na primeira vez; atualiza nas próximas. A ausência de `credential.yml` é o que marca o user como SSO (`sso: true` na API).
- **Bootstrap mode**: nenhum usuário não-system com `role: sysadmin` → todo login SSO recebe sysuser automaticamente. Quando o admin se marca na UI, o modo encerra.
- **Bug crítico em prod**: `system` user tem `role: sysadmin` no USER.md → a checagem original `!listUsers().some((u) => u.role === "sysadmin")` sempre retornava `false` → `guga` entrava como `user`. Fix: excluir `system` da checagem com `u.slug !== "system" &&`.
- **O mesmo bug existia no frontend** (`users-list.tsx`) para exibir o `BootstrapBanner` — corrigido na mesma PR.
- **Pipeline GitLab não completou o deploy** a tempo (branch `ab`, pipeline ~10 min rodando). Fix aplicado manualmente: `git pull origin ab` no servidor + `sed` no JS compilado dentro do container + `docker compose restart backbone`.
- **Container compila na imagem** — source não está dentro do container (`NO_SRC`). Para patches emergenciais: `docker exec ... sed -i` no dist + restart. Para a próxima imagem: rebuild normal via CI.
- **Validação Playwright**: `guga` entrou via Authelia, apareceu com badge SSO + badge Admin, `system` com badge Sistema. Bootstrap mode confirmado em produção.

---

**Lessons Learned:**

- A checagem de bootstrap mode deve sempre excluir usuários especiais/sistema da contagem de admins. `system` é admin técnico, não admin do produto.
- Containers de prod sem source mounted: patches de emergência são `sed` no dist; a próxima imagem via CI resolve permanentemente.
- Quando pipeline demora/falha e a correção é pequena e bem-localizada: patch manual no dist + restart é mais rápido e seguro que esperar CI.
- `docker inspect --format "{{index .Config.Labels \"com.docker.compose.project.config_files\"}}"` revela o caminho exato do compose usado para subir o container — útil quando há múltiplos compose files em `/infra/`.
- `docker compose restart` requer `--env-file` quando as variáveis de ambiente não estão no shell do usuário.
