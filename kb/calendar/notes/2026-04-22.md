**Key Exchanges:**

- **SSL cert path mismatch**: `nginx-proxy` reads certs from `/projetos/proxy/nginx/certs/live/<domain>/`, not from `/etc/letsencrypt/` directly. Manual `cp -L` required after certbot issues cert. Certbot auto-renewal refreshes `/etc/letsencrypt/` but NOT the nginx-proxy path — needs re-copy every ~60 days or a deploy-hook in `/etc/letsencrypt/renewal-hooks/deploy/`.
- **`privkey.pem` → `private.key` rename**: certbot outputs `privkey.pem`; nginx-proxy expects `private.key` — the copy command must rename it.
- **SSH inspection bootstrap**: `bash <skill>/scripts/setup-local-ssh.sh` is idempotent; sets up `~/.ssh/` with host key, config block `Host iaweb`, and keypair. Key source priority: (1) GitLab group SSH_DEPLOY_KEY via GITLAB_ACCESS_TOKEN, (2) new keypair generated locally. After setup, all inspection is `ssh iaweb 'cmd'` — no ad-hoc credentials.
- **Pre-deploy investigation is mandatory** for pre-existing `/projetos/<app>/` directories — never `docker compose up -d` on unknown state.

---

**Lessons Learned:**

- Runtime container config (`docker exec … cat`) is the source of truth, not the repo. The Caddyfile in the running container may be ahead of the repo.
- Certbot renewal hook (`/etc/letsencrypt/renewal-hooks/deploy/`) is the correct long-term fix for the cert sync problem — avoids the ~60-day manual copy.
- `deploy-only` CI pattern (GitLab deploys image built externally) is dangerous if the external CI (e.g., GitHub Actions) is not triggered by commits on the actual source-of-truth. Observed failure: GHA built stale code from a GitHub mirror that was 18 days behind GitLab.
- When upstream is behind runtime: diagnose by comparing built HTML asset paths in the running container vs what the repo would generate. Restoring lost config is not scope creep — it's sync.
- `shared-net` / `web_network` cross-project networks must not be removed without inspecting membership first.
- `suporte` user may not be in the `docker` group by default on ia-web — `usermod -aG docker` needed in bootstrap.
