**Decisions Made:**

- **Vars do CI**: project-level em `nic-lab` (id 275) com nomes canônicos `DOCKER_REGISTRY_{URL,USER,PASSWORD}` + `SSH_DEPLOY_KEY` (file). `VPS_IAWEB_*` hardcoded no `variables:` do yml (constantes da infra).
- **tsc do backbone**: `tsc --noCheck --declaration false` no Dockerfile pra destravar build (workaround). Type-check separado fica como débito arquitetural no Hono. Mudança só afeta imagem CI; type-check em IDE/dev continua intacto.
- **Commit B** (swap do vhost): admin trocou nginx-proxy de 3 proxy_pass direto (hub/chat/backbone) por 1 único (`ab-development-caddy-1:6000`) + Authelia forward-auth mantido por path. Reload zero-downtime.
- **Masking de senhas com `#`**: GitLab rejeita `masked=true` pra valores fora de base64-safe (permite só `[a-zA-Z0-9@_+=:/-]`). Aceito `masked=false` + `--password-stdin` no CI.

**Lessons Learned:**
- **Hono type explosion em escala**: cada `.route()` encadeado acumula tipo agregado que TS precisa recalcular a cada nova rota. Patologia arquitetural conhecida (não é bug pontual). Fix longo-prazo: anotar sub-apps com `const app: Hono = new Hono()` explícito. Curto-prazo: separar transpile de type-check (`tsc --noCheck`).
- **Lockfile Windows ↔ Linux**: `package-lock.json` gerado em Windows não traz `@rollup/rollup-linux-x64-gnu` (optional platform-specific). `npm install --include=optional` sozinho não resolve porque preserva lockfile. Fix: `rm package-lock.json && npm install` dentro do container. Bug npm conhecido (issue #4828).
- **GitLab masking rules**: valores precisam ser base64-safe (`[a-zA-Z0-9+/=]` + `@_:-`). Caracteres tipo `#` rejeitam `masked=true` com erro `{"message":{"value":["is invalid"]}}`. Masking de log em CI pode ser conseguido via `--password-stdin` mesmo sem a flag.
- **Bootstrap não-completo**: `/projetos/agentic-backbone` foi criado como root:root e arquivos internos suporte:suporte. `chown -R` não resolveu o dir raiz — precisou `chown` sem `-R` explícito no target. Skill deveria ter checklist "bootstrap-incompleto" com verificações de owner + .env + docker-login + grupo docker.
- **Git remote no servidor apontando pra GitHub**: legado do deploy antigo (clone via GHA). Fix: `git remote set-url origin http://gitlab.processa.info/...` (HTTP anônimo funciona — nic-lab é acessível sem auth no pull) — não precisa SSH key ou PAT no servidor.
- **DEV OVERRIDES ativas em prod**: `.env` do servidor `/projetos/agentic-backbone/.env` estava com bloco DEV OVERRIDES não-comentado. Resultado: `PROXY_UPSTREAM=host.docker.internal` no Caddy = tenta reverse_proxy pra host inexistente. Release notes pediam comentar após deploy; ninguém fez. Fix: `sed -i '/DEV OVERRIDES/,/═══/{ /^[A-Z]/s/^/# / }'`.
- **Caddyfile do container hub com porta hardcoded**: `:80` quebra a convenção do projeto (portas vêm de `.env` com PREFIX). Trocar pra `:{$HUB_PORT}` deixa o bind resolver via env runtime. Dockerfile pode `EXPOSE ${HUB_PORT}` — metadata apenas (não binda).
- **`masked=true` no GitLab API** retorna `<hidden>` como value — backup via API não consegue ler masked values em clear. Pra revert real, precisa ter a senha por outro canal (htpasswd file, password manager).
- **Separação transpile-vs-typecheck** é padrão indústria em projetos TS grandes. Quando `tsc` é o bottleneck do build e IDE já faz check em tempo real, desacoplar é legítimo (não gambiarra).
- **Naming em infra de cliente**: variáveis no GitLab do cliente não devem carregar nome de fornecedor. Se a skill prescreve `DOCKER_REGISTRY_*` genérico, implementar assim em cliente. Fornecedor no **valor** (host do registry) é OK; no **nome da var**, não.
- **Memory removida não deve ser ecoada por inércia**: o `feedback_deploy_scope` sumiu do MEMORY.md no meio da sessão e continuei citando a regra. Lição: reler `MEMORY.md` atual quando em dúvida, não confiar no snapshot inicial.
