**Lessons Learned:**
- "Runtime = fonte da verdade" quando investigando deploy legado: cristalizar Caddyfile do container rodando em vez de reinventar. `docker exec ab-development-caddy-1 cat /etc/caddy/Caddyfile` revelou path routing pronto alinhado com skill.
- Quando memory diz "sinalizar bugs app mas nunca corrigir", a exceção é config **perdida que o runtime em produção já depende**. Restauração ≠ scope creep. Fork mirror estagnado (codr/main) tinha a config; upstream (gitlab/ab) perdeu.
- `web_network` não é neutra — se o container não está nela, o proxy externo não enxerga. `docker network inspect web_network` é check obrigatório antes de qualquer vhost swap.
- `shared-net` no ab é compartilhada com `coletivos-development-kong-1` (outro projeto NIC) — dependência cross-projeto, não remover.
- `platform.mjs` ROOT vs cwd split é sutil: ROOT aponta pra repo root (`.env`, `CONTEXT_FOLDER`), cwd=INFRA pra docker compose interpretar paths relativos do compose file corretamente.
- Docker Compose interpreta paths de volumes relativos ao **diretório do compose file**, não ao cwd. Mover compose pra `infra/` exige `../data` em todos os volumes.
- `git mv docker infra/docker` direto quebrou rename tracking; resolvi com `git reset` + `git add -A` (git redescobre rename via hash do conteúdo).
- Hub tinha um nginx:alpine legado servindo landing default nginx (`/usr/share/nginx/html/index.html` era a "Welcome to nginx"), não a SPA — só o `Caddyfile` interno lidava com redirect `/` → `/hub/`. Isso é um cheiro de "imagem assada com config implícita".
- npm bug conhecido: `package-lock.json` gerado em Windows **não traz** `@rollup/rollup-linux-x64-gnu`. Build em container Linux com `npm ci` falha. Fix: regenerar lockfile em Linux ou usar `npm install --include=optional`.
